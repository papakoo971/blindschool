# MVP next steps

## 1. 제품 개요

### 제품명

blindschool

### 한 줄 정의

한국 교직원이 재직 인증 후 사용하는 익명 커뮤니티와 업무 소통 허브입니다.

### 문제 정의

- 교직원 소통이 카카오톡 단체방, 밴드, 문서, 메신저로 분산되어 있습니다.
- 솔직한 의견 제시와 공식 업무 협업이 같은 공간에서 다뤄지기 어렵습니다.
- 교직원 전용 커뮤니티는 신뢰 가능한 인증 체계가 필요합니다.

### 목표

- 교직원만 가입 가능한 커뮤니티 구축
- 익명 의견 공유와 업무 공지/자료 공유 기능 통합
- 재직증명서 기반 자동 인증 도입
- 웹과 앱이 같은 API를 쓰는 구조 준비

### 비목표

- 학생/학부모 가입
- 실시간 채팅, 음성, 영상회의
- 전국 단위 교육청 SSO 연동
- 고급 추천 알고리즘

## 2. 대상 사용자

- 교사
- 행정직원
- 상담, 보건, 사서, 기술 등 기타 교직원
- 학교 운영자
- 플랫폼 운영자
- 감사 권한자

## 3. 서비스 구조

### 모드 분리

- 익명 모드: 학교 문화, 행정, 제도, 고충, 개선 제안
- 실명 또는 준실명 모드: 공지, 자료 공유, 일정, 투표, 회의록

익명성과 실무 신뢰가 충돌하지 않도록 두 모드를 명확히 분리합니다.

### 정보 구조

- 홈: 오늘 공지, 진행 투표, 이번 주 일정, 최근 자료, 인기 글
- 커뮤니티: 자유, 고충, 제도개선, 업무 주제 게시판
- 업무 허브: 공지, 투표, 자료실, 일정
- 그룹: 학교별, 지역별, 직군별, 업무부장별 그룹
- 알림: 인증 결과, 공지, 멘션, 투표 마감
- 관리자 센터: 가입 승인, 인증 검토, 신고 처리, 권한 관리, 통계

## 4. 인증 정책

### MVP 인증 방식

재직증명서 업로드 후 자동 판정합니다. 완전 무인 승인이 아니라 점수 기반으로 자동 승인, 보류, 반려를 나눕니다.

### 가입 입력 정보

- 이름
- 휴대전화 번호
- 소속 학교명
- 직군/직무
- 재직증명서 파일(PDF, JPG, PNG)

### 자동 인증 파이프라인

1. 파일 업로드
2. 확장자, MIME, 크기, 악성 파일 검사
3. OCR 수행
4. 필수 항목 추출
5. 입력 정보와 OCR 결과 비교
6. 학교명 표준화 매칭
7. 문서 신뢰도와 위변조 위험 계산
8. 신뢰 점수 산정
9. 자동 승인, 운영자 검토, 반려 중 하나로 상태 결정

### 추출 필드

- 성명
- 학교명 또는 기관명
- 재직 상태 또는 재직 기간
- 발급일
- 문서번호 또는 발급번호
- 발급기관 직인 또는 서명 영역

## 5. 인증 점수 규칙

점수 범위는 0~100입니다.

- 85점 이상: 자동 승인
- 60~84점: 운영자 검토 보류
- 59점 이하: 자동 반려

### 가점 항목

| 영역 | 조건 | 점수 |
| --- | --- | ---: |
| 신원 일치 | 입력 이름과 OCR 이름 완전 일치 | +20 |
| 기관 일치 | 입력 학교명과 OCR 학교명 표준화 일치 | +20 |
| 재직성 | 재직 또는 근무 상태 키워드 검출 | +10 |
| 발급일 | 발급일 90일 이내 | +10 |
| 문서 완성도 | 필수 필드 5개 이상 추출 | +10 |
| 형식 신뢰 | 재직증명서 유사 템플릿 매칭 | +10 |
| 직인/서명 | 직인 또는 서명 영역 존재 | +10 |
| 문서번호 | 문서번호 또는 발급번호 추출 | +5 |
| OCR 품질 | OCR 신뢰도 평균 0.9 이상 | +5 |

### 감점 항목

| 리스크 | 조건 | 감점 |
| --- | --- | ---: |
| 날짜 위험 | 발급일 91~180일 | -10 |
| 날짜 만료 | 발급일 181일 초과 | -25 |
| 해상도 저하 | 지나치게 낮은 해상도 또는 흐림 | -10 |
| 편집 흔적 | 이미지 합성 또는 편집 가능성 높음 | -25 |
| 메타 이상 | 비정상 생성 도구 등 메타데이터 이상 | -10 |
| 이름 불일치 | 입력 이름과 OCR 이름 불일치 | -30 |
| 학교 불일치 | 입력 학교와 OCR 학교 불일치 | -30 |
| 중복 문서 | 기존 승인 계정 문서 SHA256 동일 | -40 |

### 하드룰

- 악성 파일 또는 비정상 MIME은 즉시 반려합니다.
- OCR에서 성명 또는 학교명을 추출하지 못하면 최소 보류 상태로 둡니다.
- 위변조 고위험 신호가 2개 이상이면 자동 승인하지 않고 운영자 검토로 보냅니다.

```text
score = sum(positive_rules) - sum(negative_rules)
score = clamp(score, 0, 100)

if malware_or_invalid_file:
  reject
elif missing_name_or_school:
  pending_review
elif high_risk_tamper_signals >= 2:
  pending_review
elif score >= 85:
  auto_approved
elif score >= 60:
  pending_review
else:
  rejected
```

## 6. 관리자 검토 화면

### 인증 검토 큐

- 검색: 이름, 학교, 요청 ID
- 필터: 상태, 점수, 기간, 학교
- 정렬: 점수순, 최신순
- 목록 필드: 요청 ID, 이름 마스킹, 학교, 점수, 상태, 접수 시각
- 일괄 처리: 승인, 반려, 담당자 할당

### 인증 상세 검토

- 원본 문서 미리보기
- 입력값과 OCR 추출값 비교
- 이름, 학교, 발급일, 직인, 문서번호 확인
- 리스크 신호 표시
- 검토 메모
- 반려 사유 템플릿
- 원클릭 승인/반려

### 정책/룰 관리

- 자동 승인 기준 점수
- 보류 기준 점수
- 발급일 유효 기간
- 주요 감점값
- 최근 7일 자동승인율, 수동검토율, 반려율
- 정책 변경 감사 로그

## 7. 상태 전이

```text
submitted -> auto_approved
submitted -> pending_review
submitted -> rejected
pending_review -> approved
pending_review -> rejected
```

승인 상태가 되면 `user_verification_state.is_verified`를 `true`로 업데이트합니다. 반려 상태에서는 재제출을 허용하되 일별 횟수 제한을 둡니다.
